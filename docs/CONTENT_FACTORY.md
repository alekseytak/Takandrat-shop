# Фабрика контента: что шлюз умеет, а что нет

Инструмент: `tools/factory.ts`, запускается через `npx tsx`. Модели — шлюз
OneProvider (`https://api.oneprovider.dev/v1`), ключ `ONEPROVIDER_API_KEY`.

Документ описывает измеренное, а не предполагаемое: каждый ниже пункт проверен
живым запросом 14 сентября.

## Что шлюз умеет

| Возможность | Как проверено | Итог |
| --- | --- | --- |
| Список моделей | `GET /v1/models` | 86 моделей |
| Картинки из текста и правка по фото | `POST /v1/chat/completions`, модель `gemini-3.1-flash-image` | работает, картинка приходит данными внутри markdown |
| Картинки других моделей | `gpt-image-2`, `gemini-3-pro-image`, `grok-imagine-image-2.0` | `gpt-image-2` — 400 «request body is invalid»; `gemini-3-pro-image` отвечает, но превратил картхолдер в другой предмет; `grok-imagine-image-2.0` — 502 |
| Зрение | `POST /v1/responses` с `input_image` | работает, но только данными: ссылку шлюз не скачивает и отвечает «картинки нет» |
| Зрение через chat/completions | тот же кадр | не работает: модель отвечает «вы не прикрепили изображение» |
| Размер кадра для зрения | 11, 32, 50, 64, 80, 100 КБ | примерно до 64 КБ на запрос; выше — 502 «временно недоступен», то есть та же ошибка, что при занятости шлюза |
| Видео | `POST /v1/videos/generations`, `grok-imagine-video`, `-1.5` | 503 «Video generation is not configured» — модели в списке есть, генерации нет |
| Голос | `/v1/audio/speech`, `/v1/audio/voices` | адресов нет; голосовой модели в списке тоже нет |
| Images API | `POST /v1/images/generations` | 404 «Images API is not supported for this platform» |

Вывод по заказу владельца «там и фото, и видео, и голос»: фото — да, видео и
голос этим шлюзом не делаются. Для них нужен отдельный сервис, и `factory video`
показывает это одной командой, а не обещанием.

## Конвейер фото

1. `photo <товар>` берёт исходник из каталога (`src/constants.ts` → `images[0]`),
   пишет `brief.json` с фактами о товаре и наказом модели.
2. Генерирует черновик той же картинкой на входе: правило магазина — только
   правка настоящего фото, никакой генерации товара с нуля.
3. Зрение описывает исходник и черновик по списку свойств: предмет, силуэт,
   цвет, швы, фурнитура, тиснение, отделения, фон, свет, метки поверх кадра,
   обрезка. Значения «неразличимо» и «отсутствует» приводятся к одному виду:
   иначе сверка ловит разницу между двумя ответами модели об одном кадре.
4. Отдельная модель сверяет два описания поле за полем. Различие в словах или
   подробности — не различие; различие — противоречие о том же свойстве.
5. Черновик с любым расхождением в самом изделии отклоняется и остаётся в
   `content/drafts/` как evidence, в каталог не идёт.
6. Публикация — только `publish <папка> --approve`, то есть по явному слову
   владельца, и только для прошедшего проверку. Прежние фото не перезаписываются.

## Почему проверке можно верить

`factory calibrate` прогоняет четыре случая и падает, если проверка ошиблась:

| Случай | Ждём | Получено |
| --- | --- | --- |
| исходник против самого себя | прошёл | прошёл |
| то же фото, пережатое в каталожный размер | прошёл | прошёл |
| другой товар (чехол вместо картхолдера) | отклонён | отклонён: оливковый цвет, шнур, красный фрагмент, метки на кадре |
| известный брак: черновик с выдуманным тиснением | отклонён | отклонён: выдуманные швы, тиснение-логотип, лишний карман |

Последний случай — настоящий брак, снятый этой же фабрикой. На нём прежняя
проверка «одним вопросом» говорила «видимые характеристики не изменились».
Нынешняя называет три выдуманные детали. Это и есть причина, по которой
сверка идёт по списку свойств, а не по общему впечатлению.

## Честный итог по фото

Модели этого шлюза не удерживают изделие неизменным. На одном и том же наказе
«поменяй только фон»:

- `gemini-3.1-flash-image` добавил тиснение с логотипом, дорисовал карман-лепесток,
  заменил светлую нить на тёмную, убрал вторую руку и «омолодил» кожу;
- `gemini-3-pro-image` превратил раскрытый картхолдер в закрытое портмоне.

Поэтому черновики отклоняются, и это правильный результат, а не поломка
фабрики. Пока модель не научится держать изделие, честный путь для каталога —
съёмка, а не рисование.

## Что показала съёмка

`factory describe` описывает каждое фото каталога. Итог: ни одно из 17 фото
не годится в каталог как есть. Мешают: текст и логотипы поверх кадра, водяной
знак в углу, чёрные рамки по бокам, фактурная бетонная стена вместо ровного
фона, обрезанный краем кадра товар, макросъёмка без предмета целиком, а на
одном кадре товар снят на человеке.

Это говорит о том, что каталогу нужна пересъёмка по списку свойств, а не
обработка моделями.

## Почта агента

`tools/mail.mjs` — временный ящик через API mail.tm: `init`, `address`, `list`,
`read <id>`, `wait`, `forget`. Пароль и токен лежат в `~/.takandrat/mail.json`
с правами 600, в репозиторий не попадают.

Создание ящика, вход по токену, обновление истёкшего токена и чтение списка
писем проверены живьём. Приём письма от стороннего сервиса пока не проверен:
подтверждение придёт при первой настоящей регистрации.
